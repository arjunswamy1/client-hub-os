- Slack DMs go only through `postDirectMessage()` in `_shared/slack-post.ts` (user ids only, internal team members only); channel posts only through `postToSlack()`. Why: DMs cannot enter the channel allowlist without weakening it.
- Brief acceptance is the single `accept_creative_brief_as` SQL function (tracker calls `accept_creative_brief`); brief notifications are queued by the database before any Slack call and deduped on `dedupe_key`. Why: exactly-once owner/designer notifications across both paths.
- Brief decline is the single `decline_creative_brief_as` SQL function; it never changes status or assignee, and the creative lead is resolved from `team_members.is_creative_lead`. Why: one atomic authorisation path and no silent orphaning.

- The MCP server is authored only in `src/lib/mcp/` (tools query via `supabaseForUser`, OAuth via Supabase); `supabase/functions/mcp` is generated by the Vite plugin. Why: RLS runs as the connecting user and the generated file is overwritten each build.
- New-business knowledge extraction validates in `_shared/nb-knowledge.ts` (verbatim evidence, proof points need a figure in the evidence) and always inserts `internal_only`; clearance happens only in the hub. Why: client economics must never leave CPM without a named person approving it.
- Period comparisons (same weekday / prior day / prior week) live only in `_shared/metric-comparisons.ts` (pure rules) and `_shared/metric-comparison-data.ts` (snapshots via `computeClientMetrics`); the drafter and the CPM bot both call `buildComparisonSet()`. Why: one comparison implementation, with absent-is-not-zero classification before any delta.
- `metric_revision_log` is written only by `_shared/metric-revision-log.ts`, insert-only, called after each spend sync's upsert; a trigger refuses UPDATE/DELETE. Why: provisionality must be detected from observed revisions, not assumed.
- Meta campaign rows in `ad_campaigns` are keyed by `platform_campaign_id` (name is only the latest label); the sync replaces legacy name-keyed rows for days it re-pulls. Why: renames created duplicate spend rows.
