# agent-gateway

- Agent Access Gateway lives only in `supabase/functions/agent-gateway` (own hashed keys in `agent_gateway_tokens`, separate from mcp-hub's `agent_tokens`); secrets resolve at call time through `SecretsProvider` in `_shared/agent-secrets.ts`, and only `_shared/op-sdk.ts` loads the 1Password SDK. Why: mcp-hub auth stays untouched and no secret value can land in a table or log.
- Agents call named actions from `actions.ts` only (provider + host allowlist per integration); Slack providers are refused. Why: no raw URLs, no key sent to an unexpected host.
- Meta writes are named actions in `write-actions.ts` only, queued in `agent_write_requests` by `write-flow.ts`, decided only by `decide_agent_write_request` (approver list, no self-approval), and executed once by the gateway (status poll or `agent-gateway-write-exec`) after a drift + ads_management re-check; `writes_enabled`, approvers and caps change only by the write owner (DB trigger). Why: no change reaches Meta without a named human deciding that exact change.
