# agent-gateway
- Opt-in all_accounts resolution lives only in `_shared/agent-all-accounts.ts`, shared by reads and write request/execution; grants default false, AJ-only enablement expires within 90 days, blocklist precedes the fingerprint/epoch cache; MAPPED means tied to an active client (connection selected/synced account, integration account_ref, or `client_ad_accounts`), never a grant's account list; blocklist removal/edit is AJ-only (ALWAYS trigger) and every add/remove is audited and alerted. Why: broad access cannot bypass account exclusions or human write approval.

- Agent Access Gateway lives only in `supabase/functions/agent-gateway` (own hashed keys in `agent_gateway_tokens`, separate from mcp-hub's `agent_tokens`); secrets resolve at call time through `SecretsProvider` in `_shared/agent-secrets.ts`, and only `_shared/op-sdk.ts` loads the 1Password SDK. Why: mcp-hub auth stays untouched and no secret value can land in a table or log.
- Agents call named actions from `actions.ts` only (provider + host allowlist per integration); Slack providers are refused. Why: no raw URLs, no key sent to an unexpected host.
- Meta writes are named actions in `_shared/agent-write-actions.ts` only, queued in `agent_write_requests` by `_shared/agent-write-flow.ts`, decided only by `decide_agent_write_request` (approver list, no self-approval, ownerless bots never approvable), created only through the atomic `agent_write_request_create` (Chicago-day limit, records key + key creator; the key creator may not decide), and executed once by the gateway (status poll or `agent-gateway-write-exec`) after a drift + ads_management re-check; `writes_enabled`, approvers and caps change only by the write owner (ENABLE ALWAYS triggers with no service-role bypass; see `docs/agent-gateway-write-locks.md`); execution re-checks currency and caps against live Meta values. Why: no change reaches Meta without a named human deciding that exact change.
